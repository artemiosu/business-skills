# Security policy

## Supported versions

Security fixes target the latest release and the default branch.

## Reporting

Use GitHub's private vulnerability reporting feature. It must be enabled before the first public release. If it is unavailable, do not publish exploit details; use GitHub Support to help establish a private path to the repository owner.

Include the affected skill/version, impact, reproduction conditions, and a suggested mitigation if known. Response time is best-effort while this remains a single-maintainer project.

## Scope

Relevant issues include prompt-injection paths, unsafe external actions, secret exposure, path traversal, destructive defaults, dependency compromise, misleading evaluation guarantees, and malicious contributions. Forecast disagreement or ordinary model error is not a security vulnerability unless it exposes a systematic safety failure.
